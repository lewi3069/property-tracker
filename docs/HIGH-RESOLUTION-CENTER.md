# High-resolution center trial (0.2.7)

The 13-camera layout can optionally use the selected center camera's configured main RTSP stream. The twelve surrounding cameras continue using native software-decoded grid streams. This applies to the default center in overview/Grid as well as the camera selected by activity in Auto. When activity clears, the default center and its main stream return through the existing selection policy.

Enable **Layout → Experimental high-resolution center (13 cameras)** with **Use the main stream for enlarged cameras** enabled. The feature defaults off for existing installations. It requires the existing eligible native 13-camera layout; it does not raise any device's camera limit or change phone, floating, or ordinary single-camera decoder preferences. If a camera's saved main path equals its grid path, it stays on the native grid engine.

Only the center main stream uses Media3, a SurfaceView, and a hardware decoder. Software-only codecs are excluded from this request to avoid decoding a large main stream on the CPU alongside twelve software grid streams. An unsupported stream, startup deadline, or stopped-video watchdog switches the center to its native grid stream. A five-minute per-camera cooldown also covers motion returns to that camera; expiry permits a main attempt on a later center change. Editing the main connection, recreating the viewer Activity, or toggling the high-resolution/main-stream options allows a retry. The tile reports **Grid stream · main unavailable** when fallback is active. Existing independent backoff and stall limits apply to the grid stream. Cooldowns are local to the viewer process and do not rewrite camera settings.

The previous center is retired before the new main starts. Native retirement still gates the startup coordinator, and unaffected surrounding players are reused. Media buffer targets remain 8 MiB for main and 2 MiB for grid streams; these are not limits on all codec, graphics, or process memory. No camera encoding settings, catalog entries, credentials, MQTT identities, or Home Assistant rules are changed by enabling this option.

This feature is separate from the disabled native SurfaceView memory experiment. Normal native grid rendering still has the documented Fire OS timing-allocation growth. Reducing native grid players from thirteen to twelve does not establish a memory fix. Main stream resolution and bandwidth depend on the camera's saved path and encoding; some existing entries intentionally use a grid path for both profiles because their main resolution exceeds the device's decoder dimensions.

## Validation

The first candidate passed 124 TV/core and 14 phone tests, both APK builds and lint with zero errors, package/signature checks, and eight Python tests. Installed in place on Kevin Office Cams on November 10, with its encrypted settings byte-identical immediately after installation. No other TV changed.

That candidate used TextureView for the center and latched fallback only for the current center visit. Its logs confirmed a 3840 × 2160 hardware HEVC first frame on one camera, but the default camera's main stream repeatedly failed in the hardware decoder when motion returned to it. The user reported buffering/frozen/incorrect playback and could not isolate which tiles were affected. The high-resolution option was turned off. First-frame callbacks did not establish acceptable physical playback.

The revision uses a single SurfaceView center and returns failed main streams to native grid playback, with a cooldown across motion changes. It passed 125 TV/core and 14 phone tests (139 total), both builds/lint with zero errors, and package/signature checks. On-device logs confirmed hardware HEVC 3840 × 2160 first frames on two cameras. One center attempt advanced from 1,267 to 2,488 rendered frames across successive health samples, then fell back after about two minutes. That observation overlaps layout-dialog navigation and does not establish a cause or a sustained-playback pass. The final candidate also logs the fixed fallback reason, without stream URLs or exception messages, to distinguish stream ending, deadlines, and decoder errors.

Hardware validation is in progress. This is separate from enabling SurfaceView for the twelve native tiles, which remains disabled. No public APK or wider TV rollout has been performed for this feature. The first trial's negative visual report remains a limitation until a revised physical-TV check succeeds; host counters alone cannot establish presentation quality.
